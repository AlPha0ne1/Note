# RMI registry

The RMI Registry is a process running on a RMI-Server that maintains a list of remote objects available for clients to call.
When developers want to make their Java objects available within the network, they usually bind them to an RMI registry. The registry stores all information required to connect to the object (IP address, listening port, implemented class or interface and the ObjID value) and makes it available under a human readable name (the bound name). Clients that want to consume the RMI service ask the RMI registry for the corresponding bound name and the registry returns all required information to connect.

Reference: https://book.hacktricks.xyz/pentesting/1099-pentesting-java-rmi

# Determine the names of methods available on the RMI server.

java -jar target/rmg-4.2.2-jar-with-dependencies.jar guess demo.ine.local 1099

![image](https://github.com/user-attachments/assets/7d9d0dd4-62ec-48db-941d-a892dc8c296b)

It seems like this function probably runs OS commands. Let's invoke the function to confirm if that's the case.
Use the following command to invoke the command ls -al (specifying it as a String array):

```
java -jar target/rmg-4.2.2-jar-with-dependencies.jar call demo.ine.local 1099 --bound-name CustomRMIServer 'new String[] {"ls", "-al"}' --signature 'String runCommand(String[] args)'
```

![image](https://github.com/user-attachments/assets/4376f271-cec7-40cc-b13b-c9281bc9e1e9)

Nothing is returned. So either it is a blind command injection scenario, or it is not a command injection issue at all, or maybe there is another possibility.

Under the call section for the remote-method-guesser tool, these two lines explain it all:

Notice that calling remote methods does not create any output by default. To process outputs generated by the call action, you need to use remote-method-guesser's plugin system and register a ResponseHandler. The plugin folder of this repository contains a GenericPrint plugin that is suitable for most situations.

So probably that's the case.

To confirm if we are dealing with a command execution vulnerability, we can send a command like sleep 5:

```
time java -jar target/rmg-4.2.2-jar-with-dependencies.jar call demo.ine.local 1099 --bound-name CustomRMIServer 'new String[] {"sleep", "5"}' --signature 'String runCommand(String[] args)'
```

![image](https://github.com/user-attachments/assets/37e70b8c-cf19-4bd9-be35-55c480131569)

Notice we added the time command before the command to invoke the remote method to determine the time it took to perform the function call. And it turns out that it took around 5 seconds this time, which indicates a command execution vulnerability is indeed present.

So probably the output is not being displayed by the tool, and we can use the GenericPrint plugin, as indicated on the tool page.

Send the ls -al command again, but this time we will use the GenericPrint plugin to display the results:

```
ls plugins
java -jar target/rmg-4.2.2-jar-with-dependencies.jar call demo.ine.local 1099 --bound-name CustomRMIServer 'new String[] {"ls", "-al"}' --signature 'String runCommand(String[] args)' --plugin plugins/GenericPrint.jar

```
